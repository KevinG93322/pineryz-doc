# Registration

Registration is the check that lists a vault. The wallet creates the vault. The registry reads that creation transaction from the chain. When the check passes, the vault is listed. When it fails, the vault can still exist on the chain, and it is not listed.

A listed vault is a metadata record: name, symbol, addresses, deployer, factory, creation transaction, and code hash. The assets stay in the wallet and in the vault. The record is not custody.

## What the registry requires

All of the following have to be true:

1. The chain is the chain this registry is configured for, and the configured RPC reports that same chain.
2. The hash is a transaction hash, and that chain has a successful receipt for it.
3. The receipt contains one vault-creation event from the authorized factory.
4. The event names a vault, the approved asset, a deployer, a name, and a symbol.
5. The vault is not the factory’s reference vault. That address exists only to pin the approved code. It is not a vault a business offers.
6. The factory marks the address as a vault it created.
7. The vault’s asset is the factory’s approved asset.
8. The vault’s runtime code matches the factory’s approved code for that asset.

When those checks pass, the registry stores one row. The same transaction, or the same vault address, a second time returns that row.

## Why a creation can be refused

Each refusal has a short reason. Where that text is fixed, the table uses it. The chain refusal states the chain id this registry accepts.

| Reason | What failed |
| --- | --- |
| No transaction receipt was found | The chain has no receipt for that hash. |
| That transaction did not succeed | The receipt status is a failure. |
| That transaction was not sent to the authorized factory | The call went somewhere other than the factory this registry trusts. |
| That transaction did not emit a vault creation event | The factory was called, and the creation event was absent. |
| The vault creation event could not be verified | The event was malformed, or the receipt contained more than one creation event. |
| The factory reference vault cannot be registered | The address is the bytecode reference the factory deployed for itself. |
| The factory has not registered the vault | The factory’s own record does not list this address as a created vault. |
| The vault asset does not match the factory’s approved asset | The event asset or the vault asset is not the asset this factory approves. |
| The deployed vault code does not match | The runtime code is not the code this factory approves for its asset. |
| The chain in the request is not the configured chain | The registry accepts the chain its factory is on. The reason states that chain id. |
| The registry could not reach the configured chain | The RPC call failed. |

A refused registration is stored as a failed check. The contracts are unchanged by that record. Creating again with the same name deploys another vault. It does not repair the failed check. That path is on [Create a vault](/vaultos/create-a-vault).

## What a listed vault means

A matching code hash shows that the vault was built as this factory builds vaults for its approved asset. The registry also requires the factory’s created-vault flag and one creation event. The hash alone does not list the vault.

The registry does not score the vault, assign a strategy, or attest to reserves beyond these reads. A listed vault is this factory’s vault for this asset. It is not a finding that some other factory, or some other asset, produced an equivalent product.
