# Backend development

You will build the services that let a business operate a vault after it exists. The registry already stores a vault after its creation transaction checks out. This role adds the ledger and the operator API.

The opening work is a record of deposits, withdrawals, and redemptions, and a documented API a business system can call to create, read, and operate a vault. Balances remain reads from the chain. The console becomes one client of that API. The registry does not take custody of the assets.

An SDK, reports for a firm’s own clients, and a second region come later, on [The build](/vaultos/build). They wait on a stable API shape.

## Responsibilities

- Keep the registry’s creation check: one row, after the transaction matches the factory’s approved asset and code. The checks are on [Registration](/vaultos/registration).
- Add a ledger of deposits, withdrawals, and redemptions. The ledger accounts for movements. It does not replace the chain balances.
- Design the operator API a business system can call, in Node.js and TypeScript, with PostgreSQL for the product’s own records.
- Write the tests that exercise registration, the ledger, and the API.
- Work with the engineers building the contracts and the console, so the console is one client of the same API.

## Requirements

- Experience with Node.js and TypeScript.
- Familiarity with PostgreSQL and HTTP APIs.
- Ability to explain a design clearly, in writing and in review.
- Comfort reading an existing codebase and extending the same pattern.
- Care for tests, and for stating what an API does.

## What we offer

- Work on VaultOS, from the [foundation](/vaultos/foundation) already running to the [first release](/vaultos/use-a-vault).
- A role focused on the ledger and the API a business uses to operate a vault under its own name.
- Collaboration with the people building the contracts and the console.
