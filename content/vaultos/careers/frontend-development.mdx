# Frontend development

You will build the screens a business uses to create a vault and operate it. The console already creates a vault and reads it back. This role makes that console one client of the operator API, and adds the screens for configuration, the ledger, and monitoring.

The wallet signs every transaction. VaultOS does not receive the key. A screen asks the wallet to switch to the network the product is using, and it does not submit on another chain.

Strategies, a firm’s own application, and an SDK come later, on [The build](/vaultos/build). The opening screens are the [first release](/vaultos/use-a-vault).

## Responsibilities

- Shape the flow for creating a vault under the business’s name and symbol, and for seeing it after [registration](/vaultos/registration).
- Add the screens an operator uses to set a fee, a cap, or a pause, without a control that takes holder funds.
- Show deposits, withdrawals, and redemptions from the ledger, and link the chain receipt after the wallet confirms it.
- Connect an external wallet: read the chain, request a switch, and ask the wallet to sign.
- Work with the engineers building the API and the contracts, so the console calls the same API a business system can call.

## Requirements

- Experience with React, Next.js, and TypeScript.
- Experience connecting a browser wallet: reading the chain, requesting a network switch, and asking the wallet to sign.
- Ability to explain a screen clearly, in writing and in review.
- Comfort reading an existing codebase and extending the same pattern.
- Care for what a screen promises. A screen states the action the product can perform.
